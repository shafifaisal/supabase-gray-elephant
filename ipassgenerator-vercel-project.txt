# MASTER DEVELOPMENT PROMPT
## SecurePass Tools — Vercel + Supabase + Next.js

### PROJECT GOAL

Build a complete, original, privacy-first password-security tools website with a custom content-management administration panel.

Working brand: SecurePass Tools. This is a provisional name; check domain availability and trademarks before launch.

Deployment: Vercel.

Framework: Next.js with TypeScript.

Database: Supabase PostgreSQL.

Authentication: Supabase Auth.

Styling: Tailwind CSS or a consistent accessible component system.

The website must provide multiple working password-security utilities, original educational content, technical SEO, appropriate privacy and consent controls, and preparation for Google AdSense review.

Do not copy another website's source code, text, logo or protected assets.

Do not claim that AdSense approval is guaranteed.

### 1. REQUIRED TECHNICAL STACK

Use:
- Next.js App Router and TypeScript.
- A currently supported Next.js release.
- React Server Components by default, with Client Components only when interactivity is needed.
- Vercel for hosting, deployments and CDN delivery.
- Supabase PostgreSQL for persistent data.
- Supabase Auth for administrator authentication.
- Supabase SSR integration for secure cookie-based sessions.
- PostgreSQL Row Level Security for database access control.
- Supabase Storage only where media storage is required.
- Tailwind CSS or another consistent accessible styling solution.
- Zod or equivalent validation for appropriate untrusted input.
- Vitest/Jest and browser tests as appropriate.

Use current official documentation when implementing framework-specific APIs.

Do not introduce Laravel, MySQL, a separate PHP backend or unnecessary server infrastructure.

### 5. PASSWORD GENERATOR

Implement a complete password generator with:
- Configurable length.
- Uppercase and lowercase letters.
- Numbers and symbols.
- Optional exclusion of ambiguous characters.
- Show/hide controls.
- Copy and regenerate controls.
- Validation.
- Clear feedback.
- A documented, appropriately qualified strength indicator.

Use crypto.getRandomValues() with unbiased character selection and a cryptographically secure shuffle.

Ensure enabled character groups are represented when requested. Reject impossible configurations.

Do not use Math.random() for security-sensitive generation.

Do not send generated passwords to any server, analytics provider or external API.

Never store passwords in PostgreSQL, local storage, session storage, cookies, URLs, logs or telemetry.

### 6. PASSPHRASE GENERATOR

Implement:
- Configurable word count.
- A reviewed, bundled word list.
- Secure uniform word selection using Web Crypto.
- Optional separators and capitalization.
- Copy and regenerate controls.
- An explanation of entropy and security limitations.

Do not use predictable phrases or pseudorandom generation.

Do not upload generated passphrases.

### 7. PASSWORD STRENGTH CHECKER

Implement a local-only strength checker.

Analyze:
- Length.
- Common passwords and predictable patterns.
- Repetition and sequences.
- Dictionary matches where supported.
- Actionable improvements.

Prefer a maintained, locally bundled password-strength library with dictionary support, after checking compatibility, licensing and maintenance status.

Do not submit passwords to APIs.

Do not log, store or transmit the input.

Explain that a score is an estimate and not a guarantee of safety.

### 8. ENTROPY CALCULATOR

Implement a transparent entropy calculator.

Show:
- Assumed character pool or word-selection method.
- The calculation.
- Estimated entropy in bits where appropriate.
- The impact of predictable patterns.
- Limitations of the assumptions.

Use accurate formulas and tests. Never present theoretical entropy as a guarantee against cracking.

### 9. RANDOM STRING GENERATOR

Implement:
- Configurable length.
- Character-set options.
- Ambiguous-character exclusion.
- Secure random selection.
- Copy and regenerate controls.
- Input validation.

Keep generation client-side. Do not store or transmit generated secrets.

### 10. SUPABASE DATABASE

Use PostgreSQL migrations checked into the repository.

Create appropriate schemas and migrations for:
- profiles or administrative user metadata.
- articles.
- categories.
- tags and article-tag relationships if required.
- media metadata.
- article revisions.
- site settings.
- redirects.
- audit logs.
- contact messages, if implemented.

Use foreign keys, indexes, uniqueness constraints, timestamps and appropriate deletion behavior.

Use UUID identifiers where appropriate.

Use the Supabase Auth user ID as the reference for authenticated profiles and administrative ownership.

Do not create database tables for generated passwords, passphrases or strength-checker inputs.

Use migrations rather than undocumented manual database changes. Include a documented process for applying migrations to development, preview and production databases.

Do not place privileged credentials in migrations or seed files.

### 11. ROW LEVEL SECURITY

Enable RLS on all exposed application tables.

Define and test explicit policies for:
- Public access to published, indexable articles and categories only.
- No public access to drafts, revisions, audit logs or private settings.
- Authors managing only authorized drafts.
- Editors publishing and managing permitted content.
- Administrators managing users and settings.
- Contact submissions being inaccessible to unauthorized users.
- Media access according to publication status and intended visibility.

Do not rely on frontend role checks alone.

Verify authorization in database policies and trusted server-side operations.

Grant only the privileges required by each role.

Never expose Supabase service-role or secret keys in client bundles.

Use a publishable key in the browser only with correct RLS policies and grants.

Treat user-controlled metadata and profile role fields as untrusted. Do not let a user grant themselves administrator permissions.

Test unauthorized SELECT, INSERT, UPDATE and DELETE operations.

Roles:
- Administrator.
- Editor.
- Author.

Administrators manage users, settings and all content.

Editors review, publish, unpublish and manage permitted articles.

Authors create and edit permitted drafts.

Build a professional, responsive admin panel with dashboard, article management, categories, media, settings and audit logs.
